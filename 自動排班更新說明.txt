小野人員工系統：整月自動排班更新

這份更新已完成程式整合與本機邏輯測試，尚未更新線上部署。

一、安裝（一次性）
1. 先保留目前線上的程式備份。
2. 在原 Google Apps Script 專案，以本包 Code.gs 的完整內容替換先前提供的後端程式內容。
   不要把兩份後端同時放進專案，以免重複宣告。無須執行 setupSystem。
3. 在原部署選「管理部署 → 編輯 → 版本：新版本 → 部署」，保持既有部署網址。
4. 將 index.html、app.js、config.js、style.css、auto-schedule.js、manifest.json、OneSignalSDKWorker.js 更新到原網站。
   config.js 沿用原 API 網址；若自行建立新部署才需改 API_URL。
   ZIP 原本包含一份 savage-staff-system 子目錄的相同網站，本包兩處前端都已同步。
5. 重新開啟網站並以老闆帳號登入，在「老闆後台」找到「整月自動排班」。

二、首次設定
選月份 → 載入規則與草稿。
初始早班 09:00~13:00、晚班 16:00~20:00，各日各 1 人是可修改範例。
逐人勾选可排星期與班別、每月工時上限、最多連續工作天數。
初始工時上限 200、連續天數 6 只是可調整範例，須依实际排班安排確認。
可新增時間班別，例如 09:00~14:00；計薪時數可以扣除休息時間。
需要全天班時，可把班別填為「全天班」、計薪時數填 8。
各班需求獨立計算，不建議把重疊班型當成同一個名額重複設定。
輸入店休日期，儲存規則。規則儲存在 SystemSettings，逐月沿用。

三、每月使用
1. 完成排休審核後，選月份並载入。
2. 按「產生／重新產生整月草稿」。
3. 檢查各人工時與缺人時段。系統先處理可用人數少的時段，並優先分配給目前總工時較少的人。
4. 手動換人會自動鎖定；也能新增指定日期班次後鎖定。按「檢查並儲存草稿」。
5. 重新產生時保留鎖定班次，重新計算未鎖定部分。
6. 按「確認寫入正式班表」。正式班表既有資料全數保留，只新增本次班次。
   這一步完成後，員工即可看到新增班次。需要通知時，再使用原本的「公布班表並通知全體員工」。

四、運作限制與保護
- 待審核和已核准排休都會避開；晚班休不會阻擋不重疊的早班。
- 停用員工不會排入。新增員工在規則載入後預設不參與，勾選并指定可上班別後生效。
- 工時上限依本月既有預計工時＋草稿計算；不是出勤或薪資結算。
- 連續工作天數包括現有跨月班次。既有班次視為保留，不會為修正舊衝突而刪除。
- 草稿存放在 AutoScheduleDrafts，未確認前不進入員工班表及薪資計算。
- 草稿確認前會重新比對員工、排休、班表和規則。資料有變更時需重新產生。
- 缺人不會強行排入不可上班的員工；可調整規則或鎖定安排後重算。
- 這是規則式排班，未排滿不代表數學上絕對無解；可能需手動調整部分班次再重排。
- 已確認月份不會再次追加同一份草稿。後續正式班次調整使用原後台。
- 不支援跨午夜班別。本次沒有新增自動推播。
- API 寫入使用同一把鎖；直接手動修改試算表不受 API 鎖保護，確認草稿期間請避免同時改表。

五、驗證
本機通過 11 組測試：整月需求與工時、晚休早上班、待審核及停用員工、既有全天班抵需求、全員排休缺額、工時及店休、跨月連續天數、鎖定衝突、人工草稿不自動補回、草稿不寫正式表與確認防重、資料改變後拒絕舊草稿。
前後端 JavaScript 語法檢查通過。
尚未在使用者 Google Apps Script 部署環境與手機瀏覽器實測；上線後先產生草稿檢查，再確認寫入。
